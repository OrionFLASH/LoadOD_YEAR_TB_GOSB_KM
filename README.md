# LoadOD YEAR_TB_GOSB_KM

Скрипт для массовой обработки файлов ОД (`xlsx`) с выделением последнего КМ, расчетом динамики, добавлением кластера из `OrgUnit` и выгрузкой итоговых файлов в структуру `OUT/YYYY/DD-MM`.

Текущая рабочая версия: `Main.py` v3.1+ (ускоренная обработка, расширенный прогресс, форматирование Excel и гибкий экспорт); документация — v3.4 (OrgUnit: `CLUSTER_CODE`, нормализация кода ГОСБ).

---

## 1. Что решает проект

- Загружает пачку Excel-файлов из `IN`.
- Удаляет строки с `КМ = "Серая зона"`.
- Нормализует ключи:
  - `ИНН_12` -> 12 символов;
  - `ТН 10` -> 8 символов.
- Определяет последний КМ по ключу `(ИНН_12, Код ТБ, Код ГОСБ)`.
- Формирует динамику по последнему КМ:
  - суммы прошлого/текущего ОД;
  - прирост;
  - темп прироста по правилам ToDo.
- Подтягивает `Кластер` из `IN/OrgUnit/*.csv`.
- Сохраняет результаты в `OUT/YYYY/DD-MM`.

## 4. Конфигурация (`Config.json`)

Все параметры запуска вынесены в `Config.json`.

### 4.1. Параметры и назначение

- `paths.input_folder` — папка входных `xlsx`.
- `paths.output_folder` — корень выходных файлов.
- `paths.log_folder` — папка логов.
- `paths.orgunit_folder` — папка справочника OrgUnit.
- `patterns.input_file_glob` — маска входных Excel-файлов.
- `patterns.orgunit_file_glob` — маска CSV-файлов OrgUnit.
- `excel.input_sheet` — имя листа в `xlsx`.
- `processing.max_workers` — число потоков загрузки:
  - `> 0` — фиксированное число потоков;
  - `0` — автоопределение по числу логических ядер (`os.cpu_count()`).
- `processing.xlsx_export_limit` — порог для сохранения `.xlsx`.
- `runtime.console_verbosity` — уровень консольной детализации:
  - `quiet` — только ключевые этапы и итог;
  - `normal` — сбалансированный вывод (по умолчанию);
  - `verbose` — расширенный технический прогресс.
- `columns_to_load` — список читаемых колонок из `xlsx`.
- `group_key` — ключ группировки агрегата.
- `output.layout_by_date` — раскладка по дате (`true/false`).
- `output.date_layout` — формат подпапок, текущий: `YYYY/DD-MM`.
- `output.*_basename` — базовые имена выходных файлов.

### 4.3. Документирующие ключи `_c_` / `_d_`

Для удобства в `Config.json` рядом с каждым рабочим параметром добавляются:
- ключ с префиксом `_c_...` — описание параметра (текст);
- ключ с префиксом `_d_...` — варианты/допустимые значения (текст).

Эти ключи используются только для читабельности человеком и не влияют на выполнение скрипта (код читает только “основные” ключи без префиксов).

### 4.2. Важно

- `Config.json` обязателен: без него скрипт завершится ошибкой.
- Все пути задаются относительно каталога проекта.

## 5. Входные данные

### 5.1. Основные файлы `IN/*.xlsx`

Обязательные колонки:
- `ИНН_12`
- `ТН 10`
- `Код ТБ`
- `Код ГОСБ`
- `ТБ`
- `ГОСБ`
- `КМ`
- `Дата загрузки`
- `ПРОШЛЫЙ ГОД ОД, тыс. руб.`
- `ТЕКУЩИЙ ГОД ОД, тыс. руб.`

Все временные файлы Excel (`~$...`) игнорируются.

### 5.2. Файл OrgUnit `IN/OrgUnit/*.csv`

Сопоставление с обработанными ОД: колонка **`Код ГОСБ`** в данных (после нормализации) сравнивается с **`GOSB_CODE`** в справочнике (то же семантическое поле).

Ожидаемые колонки в CSV:
- **`GOSB_CODE`** — код ГОСБ (обязательно);
- **`CLUSTER`** или **`CLUSTER_CODE`** — значение кластера (достаточно одной из колонок; типовой выгрузке соответствует `CLUSTER_CODE`).

Преобразование внутри скрипта:
- `GOSB_CODE` → `Код ГОСБ` (с нормализацией числовых кодов, чтобы «4001» и «4001.0» из Excel совпадали);
- `CLUSTER` / `CLUSTER_CODE` → `Кластер`.

Если в папке несколько файлов по маске, **файлы с `TEST` в имени сортируются в конец** — чтобы тестовый мини-справочник не перекрывал полный (`ORG_UNIT_V20 ...csv` и т.п.).

## 6. Логика обработки

1. Поиск `xlsx` по маске из `Config.json`.
2. Параллельная загрузка файлов (`ThreadPoolExecutor`).
3. Нормализация ключей и типов.
4. Удаление строк `КМ = "Серая зона"`.
5. Объединение в единый слой.
6. Агрегация по ключу `group_key`.
7. Выделение последнего КМ и КМ по датам.
8. Динамика по последнему КМ.
9. Обогащение динамики кластером из OrgUnit.
10. Сохранение выходных файлов и статистики.

### 6.1. Ускорения в текущей версии

- Векторная нормализация ключевых полей в `load_single_file()` вместо построчного `apply()`.
- Замена `groupby(...).apply(get_max_od_row)` на более быстрый выбор через `idxmax()` по группам.
- Векторный расчет `Темп прироста, %` через `numpy` вместо `apply(axis=1)`.
- Добавлен пошаговый прогресс по длительным этапам:
  - загрузка;
  - объединение;
  - raw/agg;
  - последний КМ;
  - динамика;
  - кластер;
  - статистика.
- По каждому файлу в прогрессе выводятся:
  - строки в исходном файле;
  - удалено строк с `КМ = "Серая зона"`;
  - осталось строк после фильтра;
  - время обработки файла;
  - время с начала работы программы.
- По каждому этапу выводятся:
  - время операции;
  - накопленное время с начала программы.

## 7. Расчет метрик

### 7.1. Прирост

`Прирост ОД = Сумма ТЕКУЩИЙ ГОД ОД - Сумма ПРОШЛЫЙ ГОД ОД`

### 7.2. Темп прироста (%)

- Если прошлый = 0:
  - текущий > 0 -> 100
  - текущий < 0 -> -100
  - текущий = 0 -> 0
- Иначе:
  - `(текущий - прошлый) / abs(прошлый) * 100`

## 8. Выходные файлы

Выход складывается в `OUT/YYYY/DD-MM`.

Режим выбирается **для каждой таблицы отдельно**.

Критерий: `processing.xlsx_export_limit` — лимит строк, ниже которого таблица может быть записана в XLSX.

- Если таблица помещается в XLSX (строк `< processing.xlsx_export_limit`):
  - она попадает в один общий файл `00_all_results_<TIMESTAMP>.xlsx`;
  - внутри этого файла создается отдельный лист.
- Если таблица не помещается в XLSX (строк `>= processing.xlsx_export_limit`):
  - таблица записывается в отдельный `CSV`.

Возможен смешанный режим (часть таблиц в XLSX-листах, часть в CSV).

### 8.1. Форматирование листов в XLSX-режиме

На всех листах:
- первая строка — заголовок;
- заголовок зафиксирован (`freeze panes`);
- включен автофильтр.

Форматы данных:
- `ПРОШЛЫЙ/ТЕКУЩИЙ ОД` и `Прирост` — числовой формат `#,##0.00`;
- поля с `Дата` — формат даты `DD.MM.YYYY`;
- `Темп прироста, %` — процентный формат `0.00%`.

### 8.2. Имена файлов XLSX/CSV

Имена CSV-файлов определяются базовыми префиксами из `Config.json`:
- `output.raw_basename` + `_<TIMESTAMP>.csv`
- `output.agg_basename` + `_<TIMESTAMP>.csv`
- `output.last_km_basename` + `_<TIMESTAMP>.csv`
- `output.dyn_basename` + `_<TIMESTAMP>.csv`
- `output.final_basename` + `_<TIMESTAMP>.csv` (основной итог)
- `output.stats_basename` + `_<TIMESTAMP>_files.csv` и `_<TIMESTAMP>_summary.csv`

XLSX-файл: `00_all_results_<TIMESTAMP>.xlsx` (появляется только если хотя бы одна таблица помещается в лимит).

## 11. Список основных функций (`Main.py`)

- `load_config()` — загрузка и валидация конфигурации.

- `fmt_elapsed()` — форматирование времени для консоли.
- `resolve_max_workers()` — выбор числа потоков (fixed/auto).
- `load_single_file()` — загрузка и очистка одного `xlsx`.
- `load_orgunit_mapping()` — загрузка маппинга `Код ГОСБ -> Кластер`.
- `auto_fit_worksheet()` — ширина колонок статистики.
- `should_export_to_xlsx()` — выбор XLSX/CSV для конкретной таблицы по лимиту строк.
- `apply_sheet_formatting()` — форматирование листа (заголовки, freeze, автофильтр, форматы данных).
- `write_df_to_sheet()` — запись DataFrame на лист Excel.
- `build_stats_frames()` — формирование таблиц статистики и сводки.
- `main()` — основной сценарий обработки.
